# Design — Block 01 Campaign Workspace Slice

## Status

Ready for implementation planning. This design covers the first campaign workspace slice only: campaign creation/selection, persisted campaign metadata, campaign API endpoints, Angular routes, and empty Chat/Sources workspace shells.

## Scope and non-goals

In scope:

- Persist `Campaign` records in PostgreSQL with generated opaque IDs, trimmed names, and server-owned timestamps.
- Expose `GET /api/campaigns`, `POST /api/campaigns`, and `GET /api/campaigns/{campaignId}`.
- Enforce campaign-name validation in domain/application code and case-insensitive uniqueness in PostgreSQL.
- Add Angular routes `/campaigns`, `/campaigns/:campaignId/chat`, and `/campaigns/:campaignId/sources`.
- Render explicit loading, empty, validation, conflict, not-found, recoverable-error, and success states.
- Render empty Chat and Sources shells without future-slice controls.

Out of scope:

- MediatR, repositories, base handlers, auth, accounts, teams, deletion, ingestion, AI, generated-client workflow expansion, source lifecycle scaffolding, or Internet-exposure access control.

## Architectural decisions

### Campaign identifier format

Use a database `uuid` primary key generated by the backend from `Guid.NewGuid()` and exposed as a lowercase canonical UUID string, for example `8f5f5b5b-7b4b-4b86-a7a2-59457e82dc11`.

- Public contracts treat the value as an opaque string; clients must not derive meaning from it.
- API validation accepts only the canonical UUID shape with absolute anchors: `\A[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}\z` plus successful `Guid.TryParse`. Do not use `^...$` for .NET route validation because `$` can match before a final newline while `Guid.TryParse` accepts surrounding whitespace.
- Responses serialize IDs with `guid.ToString("D").ToLowerInvariant()`.
- Malformed IDs return `400` with `code: campaign_id_invalid`.
- Well-formed but absent IDs return `404` with `code: campaign_not_found`.

### Case-insensitive uniqueness

Use a generated normalized column plus unique index instead of `citext`:

```sql
CREATE TABLE campaigns (
  id uuid PRIMARY KEY,
  name varchar(120) NOT NULL,
  name_normalized varchar(120) GENERATED ALWAYS AS (lower(name)) STORED,
  created_at timestamptz NOT NULL,
  updated_at timestamptz NOT NULL,
  CONSTRAINT ck_campaigns_name_trimmed CHECK (name = btrim(name)),
  CONSTRAINT ck_campaigns_name_length CHECK (char_length(name) BETWEEN 1 AND 120)
);

CREATE UNIQUE INDEX ux_campaigns_name_normalized ON campaigns (name_normalized);
```

Rationale: this avoids a required PostgreSQL extension, keeps the unique value inspectable, and lets the database protect concurrent duplicate creation attempts. Application code still performs friendly pre-validation, but the unique index is authoritative under races.

## Backend design

### Project structure

Add a Campaigns module under the existing API project until the repository grows enough to split assemblies:

```text
services/api/src/Api/
├── Modules/Campaigns/
│   ├── Domain/
│   │   ├── Campaign.cs
│   │   └── CampaignName.cs
│   ├── Application/
│   │   ├── CreateCampaign/
│   │   ├── GetCampaign/
│   │   └── ListCampaigns/
│   ├── Infrastructure/
│   │   ├── CampaignsDbContext.cs
│   │   ├── CampaignEntityTypeConfiguration.cs
│   │   └── Migrations/
│   └── CampaignEndpoints.cs
└── Program.cs
```

This keeps a vertical-slice shape without introducing MediatR, repositories, base handlers, or speculative shared abstractions.

### Domain model

`Campaign` owns:

- `Id: Guid`
- `Name: CampaignName`
- `CreatedAt: DateTimeOffset`
- `UpdatedAt: DateTimeOffset`

`CampaignName` is a value object/factory that trims input and returns either a valid value or `campaign_name_invalid`. Rules:

- Missing/null/whitespace fails.
- Trimmed length must be 1–120 characters.
- Persist only the trimmed name.

Creation uses server time and generated ID only. There is no update, delete, archive, or source relationship in this slice.

### Application slices

- `CreateCampaignCommand(Name)` → validates name, creates entity, saves changes, maps duplicate database violations to `campaign_name_conflict`, returns DTO.
- `ListCampaignsQuery` → returns all campaigns ordered by `createdAt` ascending then `name` ascending for stable UI rendering; no implicit active campaign.
- `GetCampaignQuery(campaignId)` → validates ID format, looks up by `Guid`, returns invalid/not-found/success result.

Use simple handler classes or static methods per feature. Handlers may depend on `CampaignsDbContext` directly because EF Core is the persistence boundary for this small module; do not add a generic repository.

### Persistence and migration

Add EF Core and Npgsql packages to `Api.csproj`; add Testcontainers/Npgsql EF dependencies to integration tests as needed. Configure:

- PostgreSQL connection string from configuration, with local Docker Compose defaults only in development configuration.
- `CampaignsDbContext` registered in `Program.cs`.
- `Campaign` mapped to table `campaigns` with snake_case columns.
- `id` as `uuid`, `name` as `varchar(120)`, timestamps as `timestamptz`.
- Generated `name_normalized` and unique index through migration SQL or EF computed column mapping.
- Check constraints for trimmed/non-empty/length safeguards.

The application, not the database, sets timestamps so API tests can assert UTC ISO output deterministically where needed. Store and return UTC.

### HTTP/API contracts

`CampaignDto`:

```json
{
  "id": "opaque-id",
  "name": "Ash Crown",
  "createdAt": "2026-09-15T12:00:00Z",
  "updatedAt": "2026-09-15T12:00:00Z"
}
```

`CreateCampaignRequest` accepts only `name`.

Endpoint mapping:

- `GET /api/campaigns` → `200 CampaignDto[]`.
- `POST /api/campaigns` → `201 CampaignDto`, `Location: /api/campaigns/{id}`.
- `GET /api/campaigns/{campaignId}` → `200 CampaignDto`.

Expected Problem Details responses include a stable `code` extension:

- `400 campaign_name_invalid`
- `409 campaign_name_conflict`
- `400 campaign_id_invalid`
- `404 campaign_not_found`
- `500 unexpected_error` through central exception handling

Problem details should also include field-level information for name failures, preferably `errors.name` or an equivalent extension consumed by the Angular adapter. Do not expose internal exception messages or database constraint names.

## Frontend design

### Routes and feature layout

```text
apps/web/src/app/features/campaigns/
├── api/campaigns-api.service.ts
├── models/campaign.model.ts
├── campaign-id.ts
├── campaign-selection.page.ts
├── campaign-workspace-shell.component.ts
├── chat-shell.page.ts
├── sources-shell.page.ts
└── state/problem-details.ts
```

Routes:

- `/campaigns` → campaign selection/creation page.
- `/campaigns/:campaignId/chat` → Chat shell route.
- `/campaigns/:campaignId/sources` → Sources shell route.
- Optional root redirect may point to `/campaigns` if the scaffold needs a useful default; it must not select a campaign.

### API adapter

Use a small handwritten adapter for Block 01:

- `listCampaigns(): Promise<Campaign[]>`
- `createCampaign(name: string): Promise<Campaign>`
- `getCampaign(id: string): Promise<Campaign>`

The adapter maps DTOs to a UI model and maps RFC 7807 `code` values into typed UI errors. This is intentionally temporary; Block 02 owns generated-client automation. Keep the adapter narrow and colocated with the campaign feature to minimize contract drift.

### State model

Use explicit discriminated unions/signals for remote state:

- `loading`
- `empty`
- `ready`
- `fieldError` for `campaign_name_invalid` and `campaign_name_conflict`
- `routeInvalid` for `campaign_id_invalid`
- `notFound` for `campaign_not_found`
- `recoverableError` for network/unexpected recoverable failures

Workspace routes resolve the campaign from the URL. They must not read a stored active-campaign preference and must not show a previous campaign while loading another route.

### UI behaviour

Visible application UI copy for Block 01 is English. This includes labels, buttons, links, headings, field-level errors, loading states, empty states, not-found/invalid-route states, recoverable-error states, and Chat/Sources unavailable-capability shell copy. Technical documentation and code identifiers remain English by project convention.

`/campaigns`:

- Shows a frontispiece-style heading and concise explanation that campaign context is required before future notes or questions.
- Shows empty state when the list is empty, with only a campaign-name form.
- Lists existing campaigns with explicit links to Chat and Sources.
- Creation success inserts or reloads the campaign list and exposes navigation; it does not silently create a hidden default.
- Name errors are associated with the name input.

Chat shell:

- Displays the resolved campaign name and route context.
- States that AI chat, source-backed querying, retrieval, citations, conversation history, streaming, and draft persistence are not available in this slice.
- Renders no query box, submit button, ingestion shortcut, citation affordance, disabled future control, or source-management action.

Sources shell:

- Displays the resolved campaign name and route context.
- States that ingestion and source management are not available in this slice.
- Renders no upload, paste, Notion import, update, remove, indexing, retry, progress, or source lifecycle action.

### Accessibility and design system

- Use semantic headings, form labels, button/link accessible names, and visible focus states.
- Associate field errors with the campaign name input using `aria-describedby` and mark invalid state with `aria-invalid` only when an error is present.
- Use `role="status"` or an equivalent polite live region for creation/list loading and retryable errors; avoid noisy announcements.
- Communicate invalid/not-found/error states with English text and structure, not color alone.
- Apply Codex Lithographica tokens: parchment surface, ink text, pimentón accents, Newsreader/editorial body, display treatment for campaign headings, and IBM Plex Mono-style metadata where available.
- Verify contrast for actual Tailwind/CSS combinations; prefer ink-primary/ink-secondary over muted text when a token combination is marginal.
- On small screens, keep links to Chat/Sources reachable in normal document flow. Do not rely on hover-only marginalia.

## Data flow

Create campaign:

```text
Campaign form → Angular adapter → POST /api/campaigns → CreateCampaign handler
→ CampaignName validation → EF insert → PostgreSQL unique index/check constraints
→ CampaignDto → adapter model → list/success state
```

Workspace route:

```text
URL campaignId → Angular route state validates UUID shape → adapter getCampaign
→ GET /api/campaigns/{campaignId} → API validates ID → EF lookup
→ success shell OR invalid/not-found/recoverable state
```

The URL remains the only active campaign source.

## Tests

### Backend unit tests

- `CampaignName` trims valid names.
- Missing, whitespace-only, and over-120-character names fail with `campaign_name_invalid`.
- `Campaign` creation sets generated ID, trimmed name, createdAt, and updatedAt.
- Campaign ID parser rejects malformed strings and accepts canonical UUID strings.

### Backend integration tests

Use `WebApplicationFactory` plus Testcontainers PostgreSQL, not an in-memory provider.

- `GET /api/campaigns` returns `[]` initially and does not select an active campaign.
- `POST /api/campaigns` creates a row and returns `201` plus `Location`.
- Creation trims names and returns UTC ISO timestamps.
- Invalid name returns `400` Problem Details with `campaign_name_invalid` and no row.
- Duplicate name with different casing returns `409 campaign_name_conflict`.
- Direct concurrent duplicate insert attempts are protected by the unique index; the losing API request maps to conflict.
- `GET /api/campaigns/{id}` returns an existing campaign.
- Malformed ID returns `400 campaign_id_invalid`.
- Unknown well-formed ID returns `404 campaign_not_found`.
- There are no delete, source, ingestion, chat, retrieval, citation, account, team, or implicit-active-campaign endpoints added by this slice.

### Frontend unit/component/route tests

- `/campaigns` loading, empty, recoverable list error, list success, creation loading, creation success.
- Field-level invalid-name and duplicate-name feedback are associated with the input.
- Campaign links navigate explicitly to `/campaigns/:id/chat` and `/campaigns/:id/sources`.
- Chat shell shows selected campaign and no future-slice controls.
- Sources shell shows selected campaign and no future-slice controls.
- Malformed ID route shows validation state without API fallback to another campaign.
- Unknown ID route shows not-found state.
- Keyboard flow can create a campaign and reach Chat/Sources links with visible focus.

### E2E smoke

One Playwright flow:

1. Open `/campaigns`.
2. Create `Ash Crown`.
3. Verify it appears in the list.
4. Navigate to Chat shell and verify unavailable AI/source-backed chat copy.
5. Navigate to Sources shell and verify unavailable ingestion/source-management copy.

Keep E2E focused; detailed failures belong at component/integration layers.

## Migration and rollback

Forward migration:

1. Add EF/Npgsql dependencies and `CampaignsDbContext`.
2. Create `campaigns` table with generated normalized name column, check constraints, timestamps, and unique index.
3. Wire application startup to use the configured PostgreSQL connection.
4. Apply migrations in local/dev before exercising the endpoints.

Rollback before real data:

- Revert code and drop the `campaigns` table/migration or reset the local PostgreSQL volume.

Rollback after local campaign rows exist:

- Export needed campaign names manually if desired, revert the migration, and recreate campaigns after reapplying a corrected migration.
- No source, ingestion, AI, citation, account, or deletion data exists in this slice, so rollback is limited to campaign metadata.

Do not add soft-delete or cascade policies for rollback; deletion semantics are explicitly out of scope.

## Tradeoffs

- UUIDs are less visually branded than prefixed IDs, but they are built into .NET/PostgreSQL, easy to validate consistently, opaque enough for public contracts, and avoid introducing an ID-generation dependency.
- A generated normalized column is slightly more schema surface than a `lower(name)` expression index, but it is inspectable and avoids requiring the `citext` extension.
- A handwritten Angular adapter creates temporary contract-drift risk, but limiting it to three methods keeps Block 01 small while Block 02 remains responsible for generated-client automation.
- Direct EF Core use in handlers couples application slices to persistence, but for this module it avoids a repository abstraction that would not add a real boundary yet.
- Route-level client ID validation improves UX for malformed URLs, but the API still performs authoritative validation so browser checks are not trusted.

## Review and delivery risk

This slice crosses backend persistence/API, frontend routes/components, and E2E. The delivery decision is to use a feature-branch chain rather than a single oversized PR:

```text
main
└─ block-01-tracker
   └─ block-01-backend
      └─ block-01-frontend
         └─ block-01-e2e-docs
```

Use GitHub's native ecosystem for PR targeting where possible: normal git branches plus `gh pr create --base <target-branch>` and `gh pr edit --base <target-branch>` for retargeting. The tracker PR is draft/no-merge; child PRs carry the reviewable work units and must keep tests/docs with the code they verify.

## Implementation notes

- Preserve `campaignId` as data isolation only; do not present it as authorization.
- Do not render disabled-looking future actions. Use explanatory copy instead.
- Keep English copy product-honest and concise.
- Update documentation only if implementation discovers a specification gap; do not change product behaviour from implementation alone.
